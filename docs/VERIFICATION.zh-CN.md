## 已完成的自动检查

amd64 和 arm64 均通过启用 race 的 Go 测试，覆盖 JSON 数值与类型精确比较、重复键、歧义末行答案、独立概率枚举、不可变题目哈希、账号及提供商锁定、禁用凭据、仅存在于运行注册表的配置凭据、取消、流完成状态缺失、保留证据的重试、私有历史权限、重启中断及基线保护。

两种原生架构使用真实 CPA C ABI 宿主、三个虚拟凭据和本机模拟上游，通过相同的 13 项集成检查：

1. 插件注册与运行时账号发现。
2. 账号和历史接口鉴权。
3. 公开静态资源不包含账号数据。
4. 真实宿主执行请求、转换响应并对受控答案评分。
5. 两个精确指定的凭据分别执行；参考答案不附加到提示词。
6. HTML 生成内容与客观题分数分开保留。
7. 单项重试创建独立历史。
8. 基线及 JSON 导出不含凭据。
9. 转换后的 token 上限截断状态不评分。
10. 取消关闭任务，不对部分回复评分。
11. 原生 Codex 回调记录保留文本与显式完成状态。
12. 刻意拒绝某凭据时，不回退到其他凭据。
13. 重启恢复原始历史、取消状态和选定基线。

每次集成验证向本机模拟上游发出 14 个请求，向真实模型发出 0 个请求。

## 已完成的浏览器检查

Chromium 使用已认证的模拟数据操作真实插件资源，覆盖以下流程：

- 账号、模型和题目选择，请求数量计算，启动、进度及完成后的评分。
- 结果筛选、原始回复及逐字段检查。
- 并排脚本化 HTML 预览：脚本在预览内执行，访问父文档被拒绝，网络连接被阻止。
- 设置基线、相匹配的基线差值、下载 JSON 及单项重试。
- 历史记录、深浅主题，以及 390px 手机宽度下无横向溢出的新建测试和结果布局。
- 自定义提示词执行，不产生虚构评分。
- 通过界面取消模型流及排队任务。
- 无浏览器页面脚本错误。

暂停流测试发现并修复了一个进度刷新问题：初始协议事件会在短文本增量到达前消耗节流窗口。改为立即发布首段文本后，实时预览恢复，界面取消测试通过。

## 保留的兼容性发现

首次隔离测试使用 musl 构建的动态库，因缺少 `libc.musl-x86_64.so.1` 加载失败。当前官方 CPA 镜像基于 Debian Bookworm，因此正式库改用 glibc。该加载失败没有被当作凭据或模型失败。

宿主即使在本地开发时也要求 `GitHubRepository` 元数据非空。插件声明的地址为 `https://github.com/Renwang-Huang/cpa-model-quality`，该地址也是源码和发行仓库。

早期安装使用独立的内存管理密钥表单，因为 CPA Manager Plus 没有向资源 iframe 传递认证。v0.1.2 与本地 Manager 构建 `v1.12.10-groups.6` 使用限定范围的父页面 API 转发替代额外登录。父页面为请求附加已有登录凭据，凭据本身不传入 iframe。独立访问仍需管理密钥。

首次真实 Codex 冒烟请求发现另一处传输差异：原生执行器提供分别独立的 `event:` 与 `data:` 回调记录，不带 SSE 行分隔符；OpenAI 兼容转换则提供带分隔符的 SSE 字节。原字节解析器忽略原生记录，将请求保留为失败且未评分。v0.1.1 同时支持完整原生记录及任意拆分的 SSE，继续要求显式完成状态。原生 Codex 模拟路径与回归测试覆盖这一差异，最初失败的生产记录也被保留。

## 部署检查

早期 arm64 库通过热加载进入已有 CPA 部署，Core 和 Manager 容器的启动时间未改变。安装前后核对了账号禁用状态、优先级、备注、账号分组元数据、已启用的时区插件及其他有效配置，并保留私有远端配置备份。

Chromium 检查了公开 Manager 侧边栏、需要认证的插件入口、主题桥接及九条凭据记录，其中七条禁用。从该页面使用 `gpt-6-luna` 发起了一次短自定义请求。首次请求暴露原生记录解析问题；升级到 v0.1.1 后，界面重试复用同一凭据和提示词，精确返回 `CPA_MODEL_QUALITY_OK`。两条记录均保留在历史中。总计只有两次真实模型请求，用于验证传输链路，不是智能基准测试。

最后一次重新打开浏览器页面遇到导航超时。重试成功后的终态、精确原始回复及未自动评分状态通过 SSH 调用内核管理 API 独立核实。这次超时作为浏览器或网络验证限制保留，不描述为浏览器验证成功。

## v0.1.2 面板登录复用

真实 CPA 宿主与新构建的 Manager 使用虚拟凭据共同验证。Chromium 登录 Manager 一次即可打开插件，无需第二次输入密码；开启 Manager 的记住凭据后，整页刷新两次仍可使用，并通过转发完成两个账号的自定义提示词批次。这两次请求仅到达模拟上游，没有浏览器脚本错误。

转发 URL 检查允许本插件端点和查询字符串，拒绝凭据管理 API、其他插件、路径穿越、片段和外部 URL。浏览器尝试通过转发访问 `/v0/management/auth-files` 返回 400。匿名直接访问插件账号数据仍被拒绝，更新后的动态库通过全部 13 项宿主集成检查。

生产 Manager 更新为 `v1.12.10-groups.6`，插件热加载为 `0.1.2`，CPA 内核未重启。前后检查核对了账号标记、优先级、备注、分组、Manager 设置及测试历史均未变化。服务器保留配置、Compose 文件及一致性 SQLite 数据库的私有回滚备份。

公开入口从 `/var/lib/cpa-ui/current` 提供独立的普通及 gzip 面板副本。首次公网检查仍收到较旧的 `groups.5` 面板，无法使用新增转发。随后现有 `cpa-ui-sync.timer` 自动同步了新版面板。当次检查中，公开版本与 Manager 面板的 SHA256 均为 `72afe4550975599654b0dd9582c561c3465d5feb62b404dded0bec007926df72`；没有修改入口配置。

同步后，Chromium 使用一次 Manager 登录核实：九个账号、其中七个禁用，没有插件额外密码表单；两次整页刷新、前往账号页面再返回、刷新账号、查看已有历史与结果及导出 JSON 均正常。导出的批次 ID 和任务数量与所选结果的 API 响应一致。匿名 bootstrap 返回 401，无浏览器页面错误。该检查没有新增模型生成请求。报告和截图保存在 `build/production-bridge-verification.json` 与 `build/production-bridge.png`。

这些检查证明的是插件对受控响应的处理行为，不衡量真实模型的智能或确认模型身份。用户主动运行的测试会产生自己的原始证据。
